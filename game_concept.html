1. 🎯 Game Overview

Valor Forged is a single-player 3D action RPG that runs entirely in a web browser. You play as an adventurer who fights monsters, earns XP and gold, levels up, and progresses through three radically different Acts. Each Act introduces a new environment, a new combat challenge, and a unique boss fight.

The core loop: Fight → Earn XP & Gold → Level Up → Unlock new Acts → Face stronger foes. After clearing all three Acts, the player enters a free-roam endgame with a level cap of 299.

2. ⚙️ Core Mechanics

2.1 Movement & Controls

  • Move: W A S D or Arrow Keys.
  • Attack: Click on a monster (Raycaster-based targeting).
  • Use Potion: Press H — heals 50% HP (max 10 potions carried).
  • Interact: Press T near an NPC (Innkeeper / Shopkeeper) to open menus.
  • Enter Boss Room: Walk into the glowing portal and press E.

2.2 Combat & Feedback

  • Click-to-attack — instant melee/ranged hit detection.
  • Visual feedback: Floating damage numbers, health bars above monsters, hit-flash (white flash), and knockback.
  • Monster AI: Melee monsters chase; ranged monsters shoot projectiles; bosses use state-machine patterns.

2.3 Progression — Leveling & Scaling

  • XP Gain: Base_XP × (Monster_Level / Player_Level) — fighting lower-level monsters gives almost no XP.
  • Gold Gain: Base_Gold + (Monster_Level × 5) — harder fights always pay more.
  • Level Cap: 299 (post-game free roam).
  • Level requirements to enter boss rooms:
    • Act 1 Boss: Level 40 (recommended 46+)
    • Act 2 Boss: Level 120 (recommended 126+)
    • Act 3 Boss: Level 200 (recommended 206+)

2.4 Death & Penalty

  • When you die, you respawn at the last Inn where you saved, with full HP.
  • You lose 10% of your current gold — painful enough to matter, not frustrating enough to quit.

2.5 Saving & Loading

  • You can only save at an Inn by speaking to the Innkeeper (T → Save).
  • Saved data (username, level, XP, gold, position, Act, potions) is stored in the browser's localStorage.
  • When you log back in, you respawn exactly at that Inn's front door.

2.6 Economy & Shops

  • Weapon Shop: Buy better weapons — each has a level requirement (e.g., "Requires Level 15").
  • Potion Shop: Buy health potions (max 10).
  • Weapons do not change the character's visual model (to save development time) — they just increase the Attack stat shown in the UI.

3. 🏰 The Three Acts — Distinct Experiences

Each Act is genuinely different — not just a reskin. They differ in environment, combat style, boss mechanics, and the skill the player must master.

Act Environment Core Mechanic Boss Attack Pattern Level Req.
1 — Verdant Valley Open grasslands, wide paths Positioning — stand still and click-trade with slow melee monsters. Charges in a straight line — dodge left/right with WASD. 40
2 — Shadowgrove Forest Dense, foggy forest with twisty paths Precision & Cover — ranged monsters shoot projectiles; use trees as cover. Shoots homing fireballs — hide behind trees to break line-of-sight. 120
3 — Highland Citadel Ruined fortress, narrow bridges over void Resource Management — manage HP, potions, and positioning on thin walkways. 3-phase (Charge → Shoot → Ground Slam) — use all skills learned. 200
📌 Examiner-ready answer: "Act 1 tests reflexes, Act 2 tests spatial awareness and precision, Act 3 tests tactical resource management — they are completely non-interchangeable."

3.1 Boss Room Entry & Hints

  • At the end of each forest path, a glowing portal (rotating torus) marks the boss entrance.
  • A stone sign next to the portal gives a hint:
    • Act 2 hint: "The trees are your shield."
    • Act 3 hint: "The bridge is narrow — choose your steps wisely."

4. 🏘️ Towns & NPCs

  • Towns are safe zones with several buildings (visual only).
  • Interactive NPCs stand outside:
    • Innkeeper — press T to Save or Cancel.
    • Weaponsmith — press T to open the weapon shop.
    • Alchemist — press T to open the potion shop.
  • No complex dialogue — just clean menu popups (Buy / Cancel).

5. 🖥️ User Interface

  • Top-left: Mini-map (2D canvas) — shows player dot, facing direction arrow, and town locations.
  • Top-right: Player stats — HP bar, Level, XP bar, Gold, Potion count.
  • Bottom-center: Context prompts — e.g., "Press T to Talk" or "Press E to Enter".
  • Start screen: Username input + Male / Female avatar selection (stored in localStorage).
  • Credits screen: Accessible from the main menu — lists every external asset, library, and sound with URLs and licenses.

6. 🏆 Post-Game (After Act 3)

  • Act 3 boss defeated → "Victory" screen appears.
  • The game does not end — you can continue playing in free-roam mode.
  • Keep fighting monsters to gain XP and gold, level up to 299 (hard cap).
  • No new content — just bragging rights and endless grinding.

8. 🔄 GitHub Actions — Deployment & Testing

We will use GitHub Actions as our CI/CD pipeline. This automates testing, building, and deployment, allowing us to track progress with every commit.

8.1 Deployment to GitHub Pages

  • The game will be hosted on GitHub Pages during development before moving to the LAMP server.
  • A workflow will automatically deploy the latest code whenever we push to the main branch.
  • Live preview URL: https://[username].github.io/[repository-name]/

8.2 Automated Testing

  • Unit Tests: We will write tests for core game logic (XP formulas, combat calculations, save/load) using Jest or Vitest.
  • Linting: ESLint will check code quality on every push.
  • E2E Tests (Optional): Cypress or Playwright can be configured to test that the game loads and basic interactions work.

8.3 Sample Workflow File

Create a file at .github/workflows/deploy.yml with the following content:

name: Deploy to GitHub Pages on: push: branches: [ "main" ] workflow_dispatch: permissions: contents: read pages: write id-token: write jobs: build: runs-on: ubuntu-latest steps: - name: Checkout uses: actions/checkout@v4 - name: Setup Node uses: actions/setup-node@v4 with: node-version: '20' - name: Install dependencies run: npm install - name: Run tests run: npm test - name: Build run: npm run build - name: Upload artifact uses: actions/upload-pages-artifact@v3 with: path: './dist' deploy: environment: name: github-pages url: ${{ steps.deployment.outputs.page_url }} runs-on: ubuntu-latest needs: build steps: - name: Deploy to GitHub Pages id: deployment uses: actions/deploy-pages@v4

9. 🛠️ Development Plan — Build Order (to avoid burnout)

Work in small, testable chunks. Do not build the whole world at once. Here is the recommended 10-day schedule:

  1. Day 1–2: WASD movement + third-person camera follow. No monsters yet — just a character walking around a flat plane.
  2. Day 3–4: Click-to-attack (Raycaster) + one basic slime monster with a health bar and simple chase AI.
  3. Day 5: Inn saving (localStorage) + Shop UI (HTML popups for weapon/potion buying).
  4. Day 6: Mini-map (2D canvas overlay with player dot and direction arrow).
  5. Day 7: Act 1 Boss — charging mechanic. Just code the boss behavior and the dodge-test.
  6. Day 8: Act 2 environment (forest trees + fog) + Act 2 Boss — homing fireballs + cover mechanic.
  7. Day 9: Act 3 environment (narrow bridges over void) + 3-phase Act 3 Boss.
  8. Day 10: Polish — health potions (H), death/respawn system, Credits screen, and final balance tweaks.
💡 Pro tip: After Day 4, you already have a playable game. Everything after is just adding content. This keeps you motivated and gives you something to show early.
